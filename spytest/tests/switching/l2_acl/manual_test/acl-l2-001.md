# Manual Test Case: L2-01 - Permit Exact Source MAC

**Test Case ID:** L2-01
**Test Suite:** L2 ACL (Layer 2 Access Control List)
**Category:** Functional Test
**Tag:** B (Both Virtual and Hardware)
**Objective:** Verify that L2 ACL rule permits traffic from a specific source MAC address

---

## Test Overview

This test validates that a Layer 2 ACL rule configured to **permit** traffic from an exact source MAC address (`00:AA:AA:AA:AA:01`) correctly forwards packets matching that source MAC.

---

## Topology

**Testbed:** `testbeds/testbed_acl.yaml`

```
  +----------------+                                    +----------------+
  |   Traffic TX   |   Ethernet0          Ethernet4    |   Traffic RX   |
  |   (Scapy/PC)   |-------------[  DUT1  ]-------------|   (Scapy/PC)   |
  |  10.0.0.1/24   |   ACL IN             ACL OUT      |  20.0.0.2/24   |
  | AA:AA:AA:AA:01 |                                   | BB:BB:BB:BB:02 |
  +----------------+                                    +----------------+
```

**Device Details:**
- **DUT1**: SONiC device at 192.168.100.163
- **TX Interface**: Ethernet0 (ingress ACL applied here)
- **RX Interface**: Ethernet4 (egress, validates forwarding)

### Phase 2: Configure L2 ACL Rule

#### Step 2.1: Create L2 ACL (Permit Source MAC)
```bash
sonic# configure terminal

# Create MAC ACL named "L2_ACL_PERMIT_SRC_MAC"
sonic(config)# mac access-list L2_ACL_PERMIT_SRC_MAC

# Add rule to permit traffic from source MAC 00:AA:AA:AA:AA:01
sonic(config-mac-acl)# permit any host 00:AA:AA:AA:AA:01 any

# Exit ACL configuration
sonic(config-mac-acl)# exit
```

**Expected Output:** ACL created successfully, no errors

---

#### Step 2.2: Apply ACL to Interface Ethernet0 (Ingress)
```bash
# Apply ACL ingress on Ethernet0
sonic(config)# interface Ethernet 0
sonic(conf-if-Ethernet0)# mac access-group L2_ACL_PERMIT_SRC_MAC in

sonic(config)# exit
```

### Phase 3: Traffic Generation and Validation

#### Step 3.1: Prepare Traffic Generator (TX Host)

**On TX Host (connected to DUT Ethernet0):**

Create Scapy script `tx_l2_acl_test.py`:
```python
#!/usr/bin/env python3
from scapy.all import *

# Test parameters
TX_IFACE = "eth0"           # TX host interface (adjust as needed)
TX_MAC = "00:AA:AA:AA:AA:01"  # Source MAC (matches ACL permit rule)
RX_MAC = "00:BB:BB:BB:BB:02"  # Destination MAC
N = 10                       # Number of packets

# Create Ethernet frames with permitted source MAC
packets = [Ether(src=TX_MAC, dst=RX_MAC)/IP(dst="20.0.0.2")/ICMP() for _ in range(N)]

# Send packets
print(f"Sending {N} packets from {TX_MAC} via {TX_IFACE}...")
sendp(packets, iface=TX_IFACE, verbose=True, inter=0.1)
print("Transmission complete.")
```

**Set interface MAC (optional, if interface MAC doesn't match):**
```bash
# On TX host
sudo ip link set dev eth0 address 00:AA:AA:AA:AA:01
sudo ip link set dev eth0 up
```

---

#### Step 3.2: Prepare Traffic Receiver (RX Host)

**On RX Host (connected to DUT Ethernet4):**

Create Scapy sniffer script `rx_l2_acl_test.py`:
```python
#!/usr/bin/env python3
from scapy.all import *

RX_IFACE = "eth1"           # RX host interface (adjust as needed)
TX_MAC = "00:AA:AA:AA:AA:01"  # Expected source MAC

print(f"Listening on {RX_IFACE} for packets from {TX_MAC}...")
print("Press Ctrl+C to stop.\n")

# Sniff packets from the permitted source MAC
pkts = sniff(iface=RX_IFACE,
             filter=f"ether src {TX_MAC}",
             count=10,
             timeout=30)

print(f"\n[RESULT] Received {len(pkts)} packets from {TX_MAC}")

if len(pkts) > 0:
    print("[PASS] Traffic forwarded successfully!")
    pkts.summary()
else:
    print("[FAIL] No packets received - ACL may be blocking traffic")
```

## Troubleshooting

### Issue 1: No Packets Received on RX Host

**Possible Causes:**
1. ACL syntax incorrect (blocking instead of permitting)
2. Interface down or not forwarding
3. MAC address mismatch in TX script vs ACL rule

**Debug Steps:**
```bash
# Check interface status
sonic# show interface status

# Check ACL configuration
sonic# show mac access-lists L2_ACL_PERMIT_SRC_MAC

# Check interface ACL binding
sonic# show running-config interface Ethernet 0

# Enable debug logging (if supported)
sonic# debug acl packet Ethernet 0
```

**Fix:**
- Verify ACL rule: `permit any host 00:AA:AA:AA:AA:01 any`
- Verify TX MAC address matches exactly: `00:AA:AA:AA:AA:01` (case-insensitive but format must match)
- Ensure interfaces are UP

---

### Issue 2: ACL Hit Counter Shows 0

**Possible Causes:**
1. Traffic not reaching Ethernet0
2. ACL not applied to interface
3. Source MAC mismatch

**Debug Steps:**
```bash
# Check interface RX counters
sonic# show interface counters | grep Ethernet0

# If RX counter is 0, traffic is not reaching DUT
# If RX counter > 0 but ACL counter = 0, ACL is not matching
```

**Fix:**
- Verify physical connectivity (cable, interface UP)
- Verify TX host MAC address configuration
- Check ACL rule syntax

---

### Issue 3: Configuration Commands Not Recognized

**Possible Causes:**
1. CLI mode incorrect (Click vs Klish)
2. SONiC version doesn't support MAC ACL syntax

**Fix:**
```bash
# Try alternative CLI syntax (Click-based)
admin@sonic:~$ sudo config acl add table L2_ACL_PERMIT_SRC_MAC L2 -p Ethernet0 -s ingress
admin@sonic:~$ sudo config acl add rule L2_ACL_PERMIT_SRC_MAC RULE_1 --src-mac 00:AA:AA:AA:AA:01 --action forward

# Verify
admin@sonic:~$ show acl table
admin@sonic:~$ show acl rule
```

## Notes

1. **MAC Address Format:**
   - SONiC typically accepts MAC addresses in format: `XX:XX:XX:XX:XX:XX`
   - Format may be case-insensitive but use uppercase for consistency

2. **Scapy Permissions:**
   - Scapy requires root/sudo for raw socket access
   - Always run Scapy scripts with `sudo`

3. **Interface Naming:**
   - Adjust `eth0`, `eth1` in Scapy scripts to match actual interface names on test hosts
   - On Linux: use `ip link show` to list interfaces

4. **Traffic Rate:**
   - Inter-packet delay of 0.1-0.5 seconds recommended to avoid overwhelming test setup
   - For high-rate testing, reduce `inter=` parameter

5. **ACL Order:**
   - L2 ACLs evaluate rules in order
   - First matching rule determines action (permit/deny)
   - If no explicit deny-all, non-matching traffic may forward (implementation-dependent)
