# BGP Test ID 2.4.7 – Session Stability After Reload (Klish)

## Overview

This test suite validates BGP session stability and recovery behavior after various reload operations in SONiC using Klish CLI. The tests verify that BGP sessions can successfully re-establish after BGP process restarts, configuration reloads, and graceful restart scenarios while meeting defined SLO requirements for downtime.

**Test ID Range**: 2.4.7.1 - 2.4.7.10
**Total Test Cases**: 10
**CLI Mode**: Klish
**Topology**: 2-node testbed (testbed_vs_2node.yaml)

## Test Objectives

- Verify BGP session recovery after BGP process restart (`systemctl restart bgp`)
- Validate session stability after configuration reload (`config reload`)
- Test graceful restart capability for minimal service disruption
- Verify BFD-enabled BGP session recovery behavior
- Validate IPv4 and IPv6 address family session recovery
- Test both eBGP and iBGP session resilience
- Verify configuration persistence across reload operations
- Validate multiple simultaneous session recovery
- Test negative scenarios (incomplete configuration)

### Test 2.4.7.1: IPv4 eBGP Numbered (/30) – BGP Process Restart on DUT1

**Objective**: Verify BGP session re-establishes after BGP process restart with minimal downtime.

**Scenario**: eBGP session over numbered IPv4 interface, restart BGP on DUT1 (local side).

#### Configuration

**DUT1 (smic_sonic1)**:
```bash
sonic-cli
configure terminal
interface Ethernet4
  ip address 10.0.0.1/30
  no shutdown
  exit
router bgp 65001
  router-id 1.1.1.1
  neighbor 10.0.0.2 remote-as 65002
  address-family ipv4 unicast
    neighbor 10.0.0.2 activate
  exit-address-family
  exit
```

**DUT2 (smic_sonic2)**:
```bash
sonic-cli
configure terminal
interface Ethernet4
  ip address 10.0.0.2/30
  no shutdown
  exit
router bgp 65002
  router-id 2.2.2.2
  neighbor 10.0.0.1 remote-as 65001
  address-family ipv4 unicast
    neighbor 10.0.0.1 activate
  exit-address-family
  exit
```

#### Verification Before Reload

```bash
# On both DUTs
show ip bgp summary
# Expected: State = Established, Uptime > 0

# On DUT1
show ip bgp neighbor 10.0.0.2
# Expected: BGP state = Established, remote AS = 65002

# On DUT2
show ip bgp neighbor 10.0.0.1
# Expected: BGP state = Established, remote AS = 65001
```

#### Test Stimulus

**On DUT1**:
```bash
# Restart BGP process on DUT1
sudo systemctl restart bgp

# Alternative command:
# sudo docker restart bgp
```

#### Verification After Reload

```bash
# Wait up to establish_timeout_s (90s) for session recovery

# On both DUTs
show ip bgp summary
# Expected: Session should re-establish within downtime_slo_s (30s)

# On DUT1
show ip bgp neighbor 10.0.0.2
# Expected: BGP state = Established

# Check logs for clean restart
show log | grep -i bgp | tail -50
# Expected: No unexpected errors, clean session re-establishment
```

#### Expected Results

- ✓ BGP session recovers to Established state
- ✓ Recovery time ≤ 30 seconds (downtime_slo_s)
- ✓ No unexpected errors in logs
- ✓ Session parameters preserved (AS numbers, router-IDs)

#### Cleanup

```bash
# DUT1
sonic-cli
configure terminal
router bgp 65001
  no neighbor 10.0.0.2
  exit

# DUT2
sonic-cli
configure terminal
router bgp 65002
  no neighbor 10.0.0.1
  exit
```

### Test 2.4.7.5: IPv4 eBGP Multihop – Graceful Restart After BGP Process Restart

**Objective**: Verify graceful restart allows session to survive BGP process restart with minimal disruption.

**Scenario**: eBGP multihop session over loopback interfaces with graceful restart enabled.

#### Configuration

**DUT1 (smic_sonic1)**:
```bash
sonic-cli
configure terminal
interface Loopback0
  ip address 1.1.1.1/32
  exit
interface Ethernet4
  ip address 10.0.0.1/30
  no shutdown
  exit
ip route 2.2.2.2/32 10.0.0.2
router bgp 65001
  router-id 1.1.1.1
  bgp graceful-restart
  neighbor 2.2.2.2 remote-as 65002
  neighbor 2.2.2.2 update-source Loopback0
  neighbor 2.2.2.2 ebgp-multihop 2
  address-family ipv4 unicast
    neighbor 2.2.2.2 activate
  exit-address-family
  exit
```

**DUT2 (smic_sonic2)**:
```bash
sonic-cli
configure terminal
interface Loopback0
  ip address 2.2.2.2/32
  exit
interface Ethernet4
  ip address 10.0.0.2/30
  no shutdown
  exit
ip route 1.1.1.1/32 10.0.0.1
router bgp 65002
  router-id 2.2.2.2
  bgp graceful-restart
  neighbor 1.1.1.1 remote-as 65001
  neighbor 1.1.1.1 update-source Loopback0
  neighbor 1.1.1.1 ebgp-multihop 2
  address-family ipv4 unicast
    neighbor 1.1.1.1 activate
  exit-address-family
  exit
```

## SLO Requirements

| Operation | Maximum Downtime | Notes |
|-----------|------------------|-------|
| BGP process restart | 30 seconds | Normal restart scenario |
| Config reload | 60 seconds | Full system reload, longer acceptable |
| Graceful restart | 120 seconds | Includes stale route timer |
| BFD recovery | 30 seconds | BFD re-establishes before BGP |

## Test Coverage Summary

This test suite covers:

- **Reload Operations**:
  - BGP process restart (`systemctl restart bgp`)
  - Configuration reload (`config reload`)
  - Graceful restart capability
  - Warm restart scenarios

- **Session Types**:
  - eBGP (different AS numbers)
  - iBGP (same AS number)
  - Numbered interfaces (/30, /64)
  - Multihop sessions (loopback-based)

- **Address Families**:
  - IPv4 unicast
  - IPv6 unicast

- **Advanced Features**:
  - BFD-enabled sessions
  - Graceful restart
  - Configuration persistence
  - Multiple simultaneous sessions

- **Test Scenarios**:
  - Local-side restart (DUT1)
  - Peer-side restart (DUT2)
  - Config save/reload
  - Negative testing (incomplete config)

## Prerequisites

1. **Platform Requirements**:
   - SONiC image with BGP support (FRRouting/FRR)
   - FRR BGP daemon functional
   - BFD support (optional, for test 2.4.7.6)
   - Graceful restart support (optional, for test 2.4.7.5)

2. **Access Requirements**:
   - Systemctl or docker control access
   - sudo privileges for service restart
   - Klish CLI access

3. **Topology Requirements**:
   - 2-node testbed (testbed_vs_2node.yaml)
   - Direct Ethernet4-to-Ethernet4 connectivity
   - Loopback interface support (for multihop tests)

## Known Limitations

1. **Virtual Testbeds**:
   - Virtual testbeds may have slower recovery times than hardware
   - SLO requirements may need adjustment for virtual environments

2. **Config Reload**:
   - Config reload time varies by platform
   - Full system reload takes longer than BGP-only restart

3. **Graceful Restart**:
   - Requires both peers to support GR capability
   - Stale route timer depends on configuration
   - Not all platforms may support GR fully

4. **BFD Support**:
   - BFD availability depends on platform support
   - Test 2.4.7.6 should be skipped if BFD not available
   - Check `bfd_enabled` variable before running BFD tests

5. **Timing Considerations**:
   - Recovery times may vary based on system load
   - Virtual environments may need longer timeouts
   - Network conditions affect session establishment time

## CLI Command Reference

### BGP Process Control

```bash
# Restart BGP service
sudo systemctl restart bgp

# Alternative: Restart BGP docker container
sudo docker restart bgp

# Check BGP service status
sudo systemctl status bgp
```

### Configuration Management

```bash
# Save running configuration
sudo config save -y

# Reload configuration (warm restart)
sudo config reload -y -f

# View running BGP configuration
show runningconfiguration bgp
```

### BGP Verification Commands

```bash
# Session status overview
show ip bgp summary
show bgp ipv6 unicast summary

# Detailed neighbor information
show ip bgp neighbor <neighbor-ip>
show bgp ipv6 unicast neighbor <neighbor-ipv6>

# Graceful restart status
show ip bgp neighbor <neighbor-ip> | grep -i "graceful restart"

# BFD status
show bfd peers
show ip bgp neighbor <neighbor-ip> | grep -i bfd

# Check logs
show log | grep -i bgp | tail -50
```

### Troubleshooting Commands

```bash
# Verify BGP process running
show processes | grep bgp

# Check interface status
show interface Ethernet4
show ip interface Ethernet4

# Verify routing table
show ip route
show ipv6 route

# Check connectivity
ping <neighbor-ip>
ping <neighbor-ipv6>
```
