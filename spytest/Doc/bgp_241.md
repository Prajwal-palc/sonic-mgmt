# BGP Test Cases — Test ID 2.4.1: IPv4 BGP Neighbor Session Establishment

## Testbed Reference
- YAML: `./testbeds/testbed_vs_2d.yaml`
- Topology Summary:
  ```
  # +----------------------+                   +----------------------+
  # |   D1 (smic_sonic1)   |===================|   D2 (smic_sonic2)   |
  # |      (IPv4/v6)       |     Ethernet4     |      (IPv4/v6)       |
  # +----------------------+                   +----------------------+
  ```
- Management access and validations performed with both `click` and `klish` (sonic-cli) modes.

## Feature Focus
- Establish and validate IPv4 BGP neighbor sessions in various configurations.
- Test both iBGP and eBGP scenarios.
- Validate both numbered and unnumbered BGP neighbors.
- Test both loopback-based and direct back-to-back peering.
- Verify session establishment and route exchange using `show ip bgp summary`.

## Test Cases

---

### Test ID 2.4.1 — BGP IPv4 Neighbor Session Establishment
- **Reference ID:** 2.4.1
- **Feature Area:** BGP IPv4 session establishment
- **Engineer:** QA Team
- **Test Objective:** Verify BGP IPv4 neighbor session forms successfully across multiple scenarios including iBGP/eBGP, numbered/unnumbered, and loopback-based/direct peering.
- **Test Setup:** Two routers connected via Ethernet4 with IPv4 connectivity and TCP/179 open as described in `testbed_vs_2d.yaml`.
- **Test Procedure:** Configure IPv4 neighbors, verify `show ip bgp summary`, and ensure Established state.
- **Expected Result:** BGP session Established; routes exchanged.
- **Actual Result:** Pass / Fail / Partial Pass

## Sub-Testcases

### Test ID 2.4.1.1 — iBGP IPv4 Numbered (Loopback-Based)
- **Test Objective:** Verify iBGP IPv4 neighbor session forms successfully using numbered loopback addresses.
- **Test Setup:**
  - D1 and D2 both in AS 65001 (iBGP)
  - Loopback interfaces configured on both devices
  - BGP peering using loopback addresses
  - IGP (OSPF/Static routes) for loopback reachability

#### Configuration - Click Mode

**D1 Configuration:**
```bash
# Configure Loopback interface
sudo config interface ip add Loopback0 1.1.1.1/32

# Configure link interface
sudo config interface ip add Ethernet4 10.0.24.1/30

# Configure BGP
sudo vtysh -c "configure terminal" \
  -c "router bgp 65001" \
  -c "bgp router-id 1.1.1.1" \
  -c "neighbor 2.2.2.2 remote-as 65001" \
  -c "neighbor 2.2.2.2 update-source Loopback0" \
  -c "address-family ipv4 unicast" \
  -c "neighbor 2.2.2.2 activate" \
  -c "network 1.1.1.1/32" \
  -c "exit-address-family"

# Configure static route for loopback reachability
sudo vtysh -c "configure terminal" \
  -c "ip route 2.2.2.2/32 10.0.24.2"
```

**D2 Configuration:**
```bash
# Configure Loopback interface
sudo config interface ip add Loopback0 2.2.2.2/32

# Configure link interface
sudo config interface ip add Ethernet4 10.0.24.2/30

# Configure BGP
sudo vtysh -c "configure terminal" \
  -c "router bgp 65001" \
  -c "bgp router-id 2.2.2.2" \
  -c "neighbor 1.1.1.1 remote-as 65001" \
  -c "neighbor 1.1.1.1 update-source Loopback0" \
  -c "address-family ipv4 unicast" \
  -c "neighbor 1.1.1.1 activate" \
  -c "network 2.2.2.2/32" \
  -c "exit-address-family"

# Configure static route for loopback reachability
sudo vtysh -c "configure terminal" \
  -c "ip route 1.1.1.1/32 10.0.24.1"
```

## Common Verification Points for All Sub-Testcases

### BGP Session Verification Checklist
1. **BGP Summary Check:**
   - Command: `show ip bgp summary`
   - Verify: Neighbor state = Established
   - Verify: MsgRcvd and MsgSent counters incrementing
   - Verify: Uptime is increasing
   - Verify: PfxRcd (Prefixes Received) > 0

2. **BGP Neighbor Details:**
   - Command: `show ip bgp neighbors <neighbor-ip or interface>`
   - Verify: BGP state = Established
   - Verify: Remote AS matches configuration
   - Verify: TCP connection established on port 179
   - Verify: Keepalive and Holdtime timers active

3. **BGP Route Table:**
   - Command: `show ip bgp`
   - Verify: Routes visible with correct next-hop
   - Verify: AS path is correct (for eBGP)
   - Verify: Origin code and local preference

4. **Routing Table:**
   - Command: `show ip route bgp`
   - Verify: BGP learned routes installed in RIB
   - Verify: Next-hop reachability

5. **Interface Status:**
   - Command: `show ip interface` or `show interface <interface>`
   - Verify: Interface is up/up
   - Verify: IP configuration is correct
   - Verify: For unnumbered, verify link-local address

## Notes and Best Practices

1. **Loopback-Based Peering:**
   - Provides redundancy if direct link fails (with proper IGP)
   - Requires additional configuration (static routes or IGP)
   - Useful for iBGP full mesh scenarios
   - eBGP requires ebgp-multihop

2. **Unnumbered Interfaces:**
   - Saves IP address space
   - Uses IPv6 link-local for BGP transport
   - Automatically handles next-hop rewriting
   - Requires interface-based neighbor configuration

3. **iBGP vs eBGP:**
   - iBGP: Same AS, requires full mesh or route reflectors
   - eBGP: Different AS, default next-hop behavior differs
   - iBGP does not modify AS path; eBGP prepends AS

4. **Router ID Selection:**
   - Must be unique per BGP speaker
   - Can be manually configured
   - Auto-selected from loopback or highest IP if not configured

5. **TCP Port 179:**
   - BGP uses TCP port 179
   - One side connects to 179, other uses ephemeral port
   - Ensure firewall rules permit bidirectional traffic
