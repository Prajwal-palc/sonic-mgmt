# BGP Test ID 2.4.8: Multi-hop Over Loopbacks

## Test Overview

**Test ID:** 2.4.8
**Test Title:** BGP Multi-hop Over Loopbacks
**Test Category:** BGP Neighbor Session Establishment

## Purpose

This test suite validates BGP multi-hop configuration over loopback interfaces, ensuring proper session establishment for both iBGP and eBGP scenarios with various TTL values and address families (IPv4/IPv6).

## Topology

```
Topology: testbeds/testbed_vs_2node.yaml

     +--------+                    +--------+
     |   D1   | Ethernet4          |   D2   |
     |        |--------------------+        |
     | (DUT1) |   10.0.0.1/30      | (DUT2) |
     +--------+   10.0.0.2/30      +--------+
        |                              |
    Loopback0                      Loopback0
    1.1.1.1/32                     2.2.2.2/32
    (or IPv6)                      (or IPv6)
```

**Minimum Topology:** 1 link between 2 DUTs (D1D2:1)

## Test Parameters

- **CLI Type:** klish (BGP configuration requires klish/vtysh mode)
- **Verification Timeout:** 120 seconds
- **Cleanup:** Automatic cleanup enabled
- **Default Keepalive:** 60 seconds
- **Default Hold Timer:** 180 seconds

## Test Cases

### Test ID 2.4.8.1: iBGP IPv4 Multi-hop Over Loopbacks (Basic)

**Objective:** Verify iBGP IPv4 session forms over loopback interfaces using multi-hop configuration.

**Test Type:** Positive

**Configuration Steps:**

#### D1 Configuration:
```bash
# Configure physical interface
configure terminal
interface Ethernet4
 ip address 10.0.0.1/30
 no shutdown
 exit

# Configure Loopback0
interface Loopback0
 ip address 1.1.1.1/32
 exit

# Configure static route to reach remote loopback
ip route 2.2.2.2/32 10.0.0.2

# Configure BGP
router bgp 65001
 bgp router-id 1.1.1.1
 neighbor 2.2.2.2 remote-as 65001
 neighbor 2.2.2.2 update-source Loopback0
 exit
exit
```

#### D2 Configuration:
```bash
# Configure physical interface
configure terminal
interface Ethernet4
 ip address 10.0.0.2/30
 no shutdown
 exit

# Configure Loopback0
interface Loopback0
 ip address 2.2.2.2/32
 exit

# Configure static route to reach remote loopback
ip route 1.1.1.1/32 10.0.0.1

# Configure BGP
router bgp 65001
 bgp router-id 2.2.2.2
 neighbor 1.1.1.1 remote-as 65001
 neighbor 1.1.1.1 update-source Loopback0
 exit
exit
```

**Verification Commands:**

```bash
# On D1
show ip bgp summary
show ip bgp neighbors 2.2.2.2

# On D2
show ip bgp summary
show ip bgp neighbors 1.1.1.1
```

**Expected Results:**
- BGP session state: **Established**
- Both neighbors show active connection
- Update source: Loopback0

## Expected Behaviors

### Positive Test Cases (2.4.8.1-2.4.8.6, 2.4.8.9-2.4.8.12)

1. **Session Establishment:**
   - BGP state transitions: Idle → Connect → OpenSent → OpenConfirm → **Established**
   - Session establishes within timeout period (120 seconds)

2. **Configuration Verification:**
   - Update source shows correct loopback interface
   - Multi-hop TTL configured as specified
   - Router IDs match configured values

3. **Reachability:**
   - Static routes installed correctly
   - Loopback addresses pingable
   - BGP packets traverse multi-hop path

### Negative Test Cases (2.4.8.7-2.4.8.8)

1. **Session Failure:**
   - BGP state remains in: Idle, Connect, or Active
   - Session does not reach Established state
   - Appropriate error messages in logs

2. **Expected Errors:**
   - TTL exceeded messages (Test 2.4.8.7)
   - Connection refused or timeout (Test 2.4.8.8)
   - Neighbor shows as administratively down or not configured

## Cleanup Procedure

After each test, perform complete BGP and interface cleanup:

```bash
# Remove BGP configuration
configure terminal
no router bgp <asn>
exit

# Remove static routes
configure terminal
no ip route 2.2.2.2/32 10.0.0.2
no ip route 1.1.1.1/32 10.0.0.1
no ipv6 route 2001:db8:2::1/128 2001:db8:10::2
no ipv6 route 2001:db8:1::1/128 2001:db8:10::1
exit

# Remove loopback interfaces
configure terminal
no interface Loopback0
no interface Loopback1
exit

# Clear interface configuration
configure terminal
interface Ethernet4
 no ip address
 no ipv6 address
 shutdown
 exit
exit
```

## Troubleshooting

### Session Not Establishing

1. **Verify reachability:**
   ```bash
   ping 2.2.2.2 source 1.1.1.1
   traceroute 2.2.2.2 source 1.1.1.1
   ```

2. **Check static routes:**
   ```bash
   show ip route 2.2.2.2
   ```

3. **Verify loopback configuration:**
   ```bash
   show interface Loopback0
   ```

4. **Check multi-hop configuration:**
   ```bash
   show running-configuration | section bgp
   ```

### TTL Issues

1. **Verify ebgp-multihop setting:**
   ```bash
   show ip bgp neighbors <neighbor-ip> | grep multihop
   ```

2. **Check hop count in path:**
   ```bash
   traceroute <neighbor-loopback>
   ```

### Timer Mismatches

1. **Verify configured timers:**
   ```bash
   show ip bgp neighbors <neighbor-ip> | grep -A 5 "Timer"
   ```

2. **Check negotiated values:**
   ```bash
   show ip bgp neighbors <neighbor-ip> | grep "Holdtime\|Keepalive"
   ```

## Notes

1. **Multi-hop Requirement:** eBGP requires explicit ebgp-multihop configuration when peering over non-directly-connected interfaces.

2. **iBGP Multi-hop:** iBGP sessions automatically support multi-hop; no explicit configuration needed.

3. **TTL Values:**
   - Default eBGP TTL: 1
   - Default iBGP TTL: 255
   - Multi-hop TTL should be >= number of hops in path

4. **Update Source:** Always specify update-source when using loopback interfaces for BGP peering.

5. **Static Routes:** Required for loopback reachability in test environment; in production, typically provided by IGP.

6. **IPv6 Considerations:** IPv6 neighbors must be activated in the ipv6 unicast address-family.

7. **Timer Negotiation:** BGP uses the lower value from each peer for keepalive and hold timers.
