### Test ID 3.2.4.1 — eBGP IPv4 Next-hop Rewrite (Directly Connected)
- **Test Objective:** When a prefix is advertised from eBGP peer A to B, B should see the next-hop as A's advertising IP (link IP).
- **Test Setup:**
  - D1 (AS 65001) and D2 (AS 65002) have IPv4 reachability on direct link
  - BGP neighbors configured and Established
  - Direct back-to-back connection via Ethernet4

#### Configuration - Klish Mode (sonic-cli)

**D1 Configuration:**
```bash
sonic-cli

  ip address 192.168.100.1/30
  no shutdown
  exit

# Configure BGP
router bgp 65001
  router-id 192.168.100.1
  neighbor 192.168.100.2 remote-as 65002
  address-family ipv4 unicast
    neighbor 192.168.100.2 activate
    network 198.51.100.0/24
    exit-address-family
  exit

exit
```

**D2 Configuration:**

**Expected Behavior Documentation:**

1. RR-client (D1) learns prefix 198.51.102.0/24 from eBGP peer with next-hop X.X.X.X

## Common Verification Points for All Sub-Testcases

### Next-hop Verification Checklist

1. **BGP Next-hop Check:**
   - Command: `show ip bgp <prefix>` or `show ipv6 bgp <prefix>`
   - Verify: NEXT_HOP field shows expected IP address
   - Verify: Next-hop matches scenario (eBGP rewrite vs iBGP preserve)

2. **Routing Table Check:**
   - Command: `show ip route <prefix>` or `show ipv6 route <prefix>`
   - Verify: Route installed in RIB/FIB
   - Verify: Next-hop matches BGP next-hop
   - Verify: Route present only when next-hop is reachable

3. **Next-hop Reachability:**
   - Command: `show ip route <next-hop>` or `ping <next-hop>`
   - Verify: Path exists to reach next-hop
   - Verify: Route resolution working correctly

4. **BGP Session Status:**

## Notes and Best Practices

1. **eBGP Next-hop Rewriting:**
   - eBGP automatically rewrites next-hop to advertising neighbor's IP
   - Applies to both IPv4 and IPv6
   - Exception: When route-map modifies next-hop explicitly

2. **iBGP Next-hop Preservation:**
   - iBGP preserves original next-hop by default
   - Requires all iBGP peers to reach the next-hop (IGP/static routes needed)
   - Use `next-hop-self` to avoid complex IGP requirements

3. **Next-hop-self Usage:**
   - Recommended for iBGP route-reflectors
   - Simplifies IGP requirements in iBGP networks
   - Can be configured per neighbor or per address-family

4. **IPv6 Link-local Next-hops:**
   - Automatically used for directly connected IPv6 BGP sessions
   - Require zone index (interface) for proper resolution
   - Show as `fe80::...%Ethernet4` in most implementations

5. **Next-hop Reachability:**
   - Critical for route installation in FIB
   - Route stays in BGP RIB even if next-hop unreachable
   - Use recursive route resolution for loopback-based peering

6. **Multi-hop Considerations:**
   - eBGP multi-hop requires explicit configuration
   - Next-hop remains the update-source IP
   - TTL must be sufficient to reach neighbor

7. **Route-Reflector Next-hop:**
   - RR preserves next-hop by default
   - Can cause reachability issues if clients can't reach next-hop
   - Consider `next-hop-self` on RR for better scalability
