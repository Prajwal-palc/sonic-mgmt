# BGP Test ID 5.1.1: VRF Route Isolation

## Test Overview

**Test ID**: 5.1.1
**Title**: VRF route isolation
**Objective**: Verify BGP VRFs advertise and learn only VRF-specific routes; no cross-VRF leakage occurs.

**Description**:
This test suite validates VRF route isolation in BGP implementations across 9 comprehensive test scenarios. It covers positive isolation scenarios, inter-VRF import/export (route-target/RD), overlapping prefixes, route leaking via global table, IPv6 VRF behavior, persistence across reboots, policy-induced leaks, and diagnostics. The tests ensure that routes advertised in one VRF are not visible in another VRF unless explicitly configured via route-target import/export or other controlled mechanisms.

## Subtests

### Test 5.1.1.1: Basic VRF isolation (separate RIBs) - IPv4

**Objective**: Configure two VRFs (VRF_A, VRF_B) on device(s), advertise distinct prefixes in each VRF and verify that prefixes are not visible in the other VRF.

**Preconditions**:
- Topology reachable and DUTs accessible (D1/D2)
- VRF functionality supported on DUTs and CLI access (klish/click)

**Test Steps**:
1. Create VRF_A and VRF_B on both DUTs
2. Configure per-VRF BGP instances (e.g., router bgp 65001 vrf VRF_A and VRF_B) and neighbors as needed
3. On VRF_A originator, advertise prefix 10.10.10.0/24 (static or network)
4. On VRF_B originator, advertise prefix 10.20.20.0/24
5. On remote VRF_A observer, run `show ip route vrf VRF_A` and `show ip bgp vrf VRF_A` to confirm presence of 10.10.10.0/24 and absence of 10.20.20.0/24
6. Repeat symmetric check on VRF_B observer

**Configuration Example (D1)**:
```bash
# Create VRFs
configure terminal
ip vrf VRF_A
exit
ip vrf VRF_B
exit

# Bind interfaces to VRFs (if needed)
interface Ethernet4
 ip vrf forwarding VRF_A
 ip address 10.1.1.1/30
exit

# Configure BGP for VRF_A
router bgp 65001 vrf VRF_A
 neighbor 10.1.1.2 remote-as 65002
 address-family ipv4 unicast
  network 10.10.10.0/24
  neighbor 10.1.1.2 activate
 exit-address-family
exit

# Configure BGP for VRF_B
router bgp 65001 vrf VRF_B
 neighbor 10.2.2.2 remote-as 65002
 address-family ipv4 unicast
  network 10.20.20.0/24
  neighbor 10.2.2.2 activate
 exit-address-family
exit
```

**Verification Commands**:
```bash
# Verify VRF_A routes
show ip route vrf VRF_A
show ip bgp vrf VRF_A

# Verify VRF_B routes
show ip route vrf VRF_B
show ip bgp vrf VRF_B
```

**Expected Results**:
- `show ip route vrf VRF_A` contains 10.10.10.0/24 and NOT 10.20.20.0/24
- `show ip bgp vrf VRF_A` shows only VRF_A prefixes
- `show ip route vrf VRF_B` contains 10.20.20.0/24 and NOT 10.10.10.0/24
- `show ip bgp vrf VRF_B` shows only VRF_B prefixes
- No route leakage between VRFs

**Timeout**: 90 seconds

**Cleanup**:
- Withdraw test prefixes
- Remove BGP VRF configurations
- Remove VRFs

### Test 5.1.1.3: VRF import/export using route-target (RT) - positive controlled leak

**Objective**: Validate controlled route import/export between VRFs via route-target (RT) — routes appear only when RT import/export configured.

**Preconditions**:
- BGP VPN/VRF route-target/RT functionality available and supported (MP-BGP)

**Test Steps**:
1. Configure VRF_A with RT export RT:65001:100 and VRF_B with RT import RT:65001:100
2. Advertise prefix 10.100.100.0/24 in VRF_A
3. Verify that VRF_B learns the prefix only after RT import configured

**Configuration Example (D1)**:
```bash
# Configure VRF_A with RT export
router bgp 65001 vrf VRF_A
 address-family ipv4 unicast
  route-target export 65001:100
  network 10.100.100.0/24
 exit-address-family
exit

# Configure VRF_B with RT import
router bgp 65001 vrf VRF_B
 address-family ipv4 unicast
  route-target import 65001:100
 exit-address-family
exit
```

**Verification Commands**:
```bash
show bgp ipv4 unicast vrf VRF_B | grep 10.100.100.0
show bgp vpnv4 unicast all
```

**Expected Results**:
- Without RT configured: no leak between VRFs
- With RT configured: routes are imported into VRF_B
- RT values present in route-target attributes for advertised prefixes

**Timeout**: 120 seconds

**Cleanup**:
- Remove RT import/export configuration
- Withdraw prefixes

**Notes**:
- This test may require MP-BGP feature and additional BGP-VPN config
- Mark as LAB/MANUAL if unsupported on testbed

### Test 5.1.1.6: Overlapping prefixes in different VRFs (same prefix different VRFs)

**Objective**: Verify same prefix can exist in VRF_A and VRF_B without conflict and is kept isolated.

**Preconditions**:
- Both VRFs configured
- Each has static route for 10.10.10.0/24 to different next-hops

**Test Steps**:
1. Configure 10.10.10.0/24 in VRF_A pointing to NH_A (e.g., 10.1.1.2)
2. Configure 10.10.10.0/24 in VRF_B pointing to NH_B (e.g., 10.2.2.2)
3. Verify `show ip route vrf VRF_A 10.10.10.0` returns NH_A; VRF_B returns NH_B

**Configuration Example (D1)**:
```bash
# Static route in VRF_A
ip route vrf VRF_A 10.10.10.0/24 10.1.1.2

# Static route in VRF_B
ip route vrf VRF_B 10.10.10.0/24 10.2.2.2
```

**Verification Commands**:
```bash
show ip route vrf VRF_A 10.10.10.0
show ip route vrf VRF_B 10.10.10.0
```

**Expected Results**:
- Each VRF resolves the overlapping prefix to its own next-hop
- No ambiguity in forwarding
- Overlapping prefixes safely isolated per-VRF with independent forwarding entries

**Timeout**: 90 seconds

**Cleanup**:
- Remove test static routes

**Expected Results**:
- Captured NLRI includes RD/RT attributes for VRF routes

**Timeout**: 180 seconds
