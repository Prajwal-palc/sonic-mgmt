# BGP Test ID 2.4.4: TCP Port 179 Blocked Prevents BGP Session

## Overview

**Test ID:** 2.4.4
**Title:** TCP port 179 blocked prevents BGP session
**Objective:** Verify BGP fails when TCP/179 is blocked between neighbors and recovers when unblocked.

**Topology:** `./testbeds/testbed_vs_2node.yaml`

**Test Description:**
This test suite validates that BGP session establishment requires TCP port 179 connectivity. When port 179 is blocked via iptables, ACLs, or network firewalls, BGP sessions should fail to establish. When the block is removed, sessions should recover to Established state.

**Notes:**
- Tests assume topology with two routers (aliases D1 and D2) connected and otherwise reachable
- Modify IPs, interface names, and ACL/iptables commands to match actual testbed
- VS platform uses iptables; HW platform uses ACL engine
- Root/privilege required for iptables modifications
- Tests should clean up firewall rules on completion or failure

## Test Case 2.4.4.3: Block TCP/179 via SONiC ACL (Hardware/Production-Like Test)

### Objective
Apply SONiC ACL or hardware ACL to drop TCP dst-port 179 between D1 and D2 to emulate production firewall behavior.

### Platform Support
- **Primary:** Hardware platforms with ACL support
- **Secondary:** SONiC virtual switch with ACL engine

### Preconditions
- Device supports ACL configuration
- User has privileges to create/modify ACLs
- ACL changes are reversible
- Will not disrupt unrelated traffic in CI

### Configuration Steps

#### Step 1: Create ACL to Block BGP Traffic

**On D1 (using SONiC config commands):**
```bash
# Create ACL table
sudo config acl add table ACL_BGP_BLOCK L3 --description "Block BGP TCP/179 for test 2.4.4.3" --stage INGRESS

# Add rule to drop TCP dst-port 179 from D2
sudo config acl add rule ACL_BGP_BLOCK RULE_DROP_BGP \
  --src-ip 10.0.0.2/32 \
  --ip-protocol 6 \
  --l4-dst-port 179 \
  --packet-action DROP \
  --priority 10

# Apply ACL to interface facing D2
sudo config acl add table ACL_BGP_BLOCK interface Ethernet0 --stage INGRESS

# Verify ACL configuration
sudo show acl table ACL_BGP_BLOCK
sudo show acl rule ACL_BGP_BLOCK
```

**Alternative using sonic-cli (if available):**
```bash
sonic-cli
configure terminal
ip access-list ACL_BGP_BLOCK
  seq 10 deny tcp 10.0.0.2/32 any eq 179
exit
interface Ethernet0
  ip access-group ACL_BGP_BLOCK in
exit
exit
show ip access-lists ACL_BGP_BLOCK
```

#### Step 2: Wait for ACL to Apply

```bash
# Wait 10 seconds for ACL to be programmed
sleep 10
```

#### Step 3: Verify BGP Session Blocked

**On D1:**
```bash
# Poll BGP status for up to blocked_wait_seconds (30s)
for i in {1..6}; do
  echo "Check $i/6:"
  sudo vtysh -c "show ip bgp summary" | grep 10.0.0.2
  sleep 5
done
```
**Expected:** State should NOT be Established (Active/Connect/Idle)

**Check ACL hit counters:**
```bash
sudo show acl rule ACL_BGP_BLOCK RULE_DROP_BGP
```
**Expected:** Packet counter should increment, proving ACL is matching BGP traffic

**Alternative counter check:**
```bash
sudo aclshow -a
# Look for ACL_BGP_BLOCK and verify hit counts
```

#### Step 4: Remove ACL and Verify Recovery

**On D1:**
```bash
# Remove ACL from interface
sudo config acl remove table ACL_BGP_BLOCK interface Ethernet0

# Delete ACL rule
sudo config acl remove rule ACL_BGP_BLOCK RULE_DROP_BGP

# Delete ACL table
sudo config acl remove table ACL_BGP_BLOCK

# Verify ACL removed
sudo show acl table | grep ACL_BGP_BLOCK
# Expected: No output
```

**Verify BGP Recovery:**
```bash
# Wait up to recover_wait_seconds (60s)
for i in {1..12}; do
  echo "Recovery check $i/12:"
  sudo vtysh -c "show ip bgp summary" | grep 10.0.0.2
  STATE=$(sudo vtysh -c "show ip bgp summary json" | jq -r '.peers."10.0.0.2".state')
  if [ "$STATE" = "Established" ]; then
    echo "Session recovered!"
    break
  fi
  sleep 5
done
```

### Verification

#### ACL Configuration Verification
```bash
# Before removal, verify ACL is active
sudo show acl table ACL_BGP_BLOCK
sudo show acl rule ACL_BGP_BLOCK RULE_DROP_BGP
```
**Expected:** Table and rule should be displayed with correct parameters

#### ACL Counter Verification
```bash
# Check that ACL matched packets
sudo aclshow -a | grep ACL_BGP_BLOCK
```
**Expected:** Non-zero packet counts for RULE_DROP_BGP

#### BGP State Verification
```bash
# While ACL active
sudo vtysh -c "show ip bgp summary"
# Expected: Session not Established

# After ACL removal
sudo vtysh -c "show ip bgp summary"
# Expected: Session Established within 60s
```

### Expected Results

1. **ACL Active:**
   - BGP session fails to establish or drops if already up
   - `show ip bgp summary` shows non-Established state
   - ACL counters increment for matched BGP packets
   - No BGP messages successfully exchanged

2. **ACL Removed:**
   - BGP session recovers to Established within recover_wait_seconds
   - ACL counters stop incrementing
   - Normal BGP operation resumes

3. **Hardware Behavior:**
   - ACL processed in hardware (ASIC) for production-like testing
   - ACL counters provide definitive proof of traffic match
   - Performance not impacted by software iptables

### Cleanup

```bash
# On D1 (idempotent cleanup)
sudo config acl remove table ACL_BGP_BLOCK interface Ethernet0 2>/dev/null || true
sudo config acl remove rule ACL_BGP_BLOCK RULE_DROP_BGP 2>/dev/null || true
sudo config acl remove table ACL_BGP_BLOCK 2>/dev/null || true

# Verify cleanup
sudo show acl table | grep ACL_BGP_BLOCK
# Expected: No output
```

## Test Case 2.4.4.4: Block TCP/179 Using Intermediate Host/Netfilter (Test Host Firewall)

### Objective
Simulate network firewall by blocking TCP/179 on an intermediate test host that sits on the path. Useful when DUT kernel/ACL access is restricted.

### Preconditions
- A controllable intermediate host exists on the path between D1 and D2
- Root access to intermediate host
- Traffic between D1 and D2 routes through intermediate host

### Topology
```
D1 (10.0.0.1) <---> Intermediate Host (10.0.0.254) <---> D2 (10.0.0.2)
```

### Configuration Steps

#### Step 1: Identify Intermediate Host

**On intermediate host:**
```bash
# Verify host can see traffic between D1 and D2
sudo tcpdump -i any host 10.0.0.1 and host 10.0.0.2 -c 10
# Expected: Should see traffic between DUTs
```

#### Step 2: Configure BGP on D1 and D2
Same as test 2.4.4.1

#### Step 3: Apply Firewall Rule on Intermediate Host

**On intermediate host:**
```bash
# Enable forwarding (if not already enabled)
sudo sysctl -w net.ipv4.ip_forward=1

# Add iptables rule to drop TCP/179 between D1 and D2
sudo iptables -I FORWARD -p tcp --dport 179 -s 10.0.0.1 -d 10.0.0.2 -j DROP
sudo iptables -I FORWARD -p tcp --dport 179 -s 10.0.0.2 -d 10.0.0.1 -j DROP

# Verify rules
sudo iptables -L FORWARD -n -v | grep 179
```
**Expected Output:**
```
    0     0 DROP       tcp  --  *      *       10.0.0.1             10.0.0.2             tcp dpt:179
    0     0 DROP       tcp  --  *      *       10.0.0.2             10.0.0.1             tcp dpt:179
```

#### Step 4: Verify BGP Session Fails

**On D1 and D2:**
```bash
# Wait blocked_wait_seconds (30s)
sleep 30

# Check BGP status
sudo vtysh -c "show ip bgp summary"
```
**Expected:** Session not Established on both DUTs

#### Step 5: Capture Traffic on Intermediate Host

**On intermediate host:**
```bash
# Start packet capture to prove packets are being dropped
sudo tcpdump -i any -nn 'tcp port 179 and (host 10.0.0.1 or host 10.0.0.2)' -w /tmp/intermediate_bgp_block.pcap -c 100 &
TCPDUMP_PID=$!

# Let it run during the test
sleep 30

# Stop capture
sudo kill $TCPDUMP_PID 2>/dev/null || true

# Analyze
sudo tcpdump -r /tmp/intermediate_bgp_block.pcap -nn
```
**Expected:** Should see SYN packets arriving but being dropped (no forwarding)

#### Step 6: Remove Firewall Rules and Verify Recovery

**On intermediate host:**
```bash
# Remove DROP rules
sudo iptables -D FORWARD -p tcp --dport 179 -s 10.0.0.1 -d 10.0.0.2 -j DROP
sudo iptables -D FORWARD -p tcp --dport 179 -s 10.0.0.2 -d 10.0.0.1 -j DROP

# Verify removal
sudo iptables -L FORWARD -n | grep 179
# Expected: No output
```

**On D1 and D2:**
```bash
# Wait up to recover_wait_seconds (60s)
for i in {1..12}; do
  echo "Recovery check $i/12:"
  sudo vtysh -c "show ip bgp summary" | grep "10.0.0"
  sleep 5
done
```
**Expected:** Both DUTs show Established within 60s

### Verification

#### Traffic Capture Analysis
```bash
# On intermediate host
sudo tcpdump -r /tmp/intermediate_bgp_block.pcap -nn 'tcp[tcpflags] & tcp-syn != 0'
```
**Expected:** SYN packets visible, but no corresponding SYN-ACK (packets dropped)

#### Firewall Counter Verification
```bash
# On intermediate host (before removing rules)
sudo iptables -L FORWARD -n -v -x | grep 179
```
**Expected:** Non-zero packet counts proving traffic was matched and dropped

### Expected Results
- Intermediate firewall successfully blocks BGP session establishment
- Packet capture shows SYN attempts arriving at intermediate host
- BGP session down on both DUTs during block
- Session recovers to Established after firewall rules removed
- Method validates BGP behavior when network infrastructure blocks traffic (not just DUT)

### Cleanup
```bash
# On intermediate host
sudo iptables -D FORWARD -p tcp --dport 179 -s 10.0.0.1 -d 10.0.0.2 -j DROP 2>/dev/null || true
sudo iptables -D FORWARD -p tcp --dport 179 -s 10.0.0.2 -d 10.0.0.1 -j DROP 2>/dev/null || true
sudo rm -f /tmp/intermediate_bgp_block.pcap
```

## Test Case 2.4.4.5: Negative Control - Block Unrelated Port (Ensure BGP Unaffected)

### Objective
Demonstrate that blocking an unrelated TCP port does not affect BGP; validates test specificity and confirms test methodology.

### Preconditions
- BGP session is Established initially
- Root/sudo access to DUT or intermediate host

### Configuration Steps

#### Step 1: Verify BGP Session Established

**On D1:**
```bash
sudo vtysh -c "show ip bgp summary" | grep 10.0.0.2
```
**Expected:** State = Established

#### Step 2: Block Unrelated Port (TCP/22 - SSH)

**On D1:**
```bash
# Add iptables rule to DROP TCP port 22 (SSH) between peers
sudo iptables -I INPUT -p tcp --dport 22 -s 10.0.0.2 -j DROP
sudo iptables -I OUTPUT -p tcp --dport 22 -d 10.0.0.2 -j DROP

# Verify rules
sudo iptables -L -n -v | grep "dpt:22"
```
**Expected Output:**
```
    0     0 DROP       tcp  --  *      *       10.0.0.2             0.0.0.0/0            tcp dpt:22
    0     0 DROP       tcp  --  *      *       0.0.0.0/0            10.0.0.2             tcp dpt:22
```

**Wait short period (30s) and continuously verify:**

```bash
for i in {1..6}; do
```

**On D1 (using tc netem to drop 100% of TCP/179 traffic intermittently):**

```bash
# Define test parameters
INTERFACE="Ethernet0"
CYCLES=5
BLOCK_DURATION=15  # seconds to block
UNBLOCK_DURATION=20  # seconds to allow traffic

# Function to apply block
apply_block() {
  sudo tc qdisc add dev $INTERFACE root handle 1: prio
  sudo tc qdisc add dev $INTERFACE parent 1:3 handle 30: netem loss 100%
  sudo tc filter add dev $INTERFACE protocol ip parent 1:0 prio 3 u32 \
    match ip dport 179 0xffff flowid 1:3
  sudo tc filter add dev $INTERFACE protocol ip parent 1:0 prio 3 u32 \
    match ip sport 179 0xffff flowid 1:3
  echo "Block applied at $(date)"
}

# Function to remove block
remove_block() {
  sudo tc qdisc del dev $INTERFACE root 2>/dev/null || true
  echo "Block removed at $(date)"
}

# Run intermittent blocking cycles
for i in $(seq 1 $CYCLES); do
  echo "=== Cycle $i/$CYCLES ==="

  # Apply block
  apply_block
  sleep $BLOCK_DURATION

  # Remove block
  remove_block
  sleep $UNBLOCK_DURATION

  # Check BGP state
  sudo vtysh -c "show ip bgp summary" | grep 10.0.0.2
done

# Ensure cleanup
remove_block
```

### Test Execution Best Practices

1. **Pre-test Validation:**
   - Verify baseline connectivity (ping between DUTs)
   - Verify baseline BGP session (Established before test)
   - Document initial state (logs, uptime, route count)

2. **During Test:**
   - Use consistent timing (blocked_wait, recover_wait)
   - Capture logs and pcaps continuously
   - Poll BGP status at regular intervals (5s)
   - Document exact timing of block apply/remove

3. **Post-test Validation:**
   - Verify complete recovery (Established state)
   - Verify no lingering firewall rules
   - Verify no configuration changes persist
   - Check for unexpected errors in logs

4. **Cleanup:**
   - Remove all iptables/ACL rules (idempotent)
   - Restore BGP configuration to baseline
   - Remove temporary files and captures
   - Verify no side effects on other tests

5. **CI/CD Integration:**
   - Ensure tests are isolated (no cross-test interference)
   - Use proper teardown even on failure (try/finally pattern)
   - Validate test host has required privileges
   - Check disk space before packet captures
   - Set appropriate test timeouts (5-10 minutes per subtest)
