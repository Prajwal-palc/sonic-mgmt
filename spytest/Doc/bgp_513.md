# BGP Test ID 5.1.3: Overlapping Prefixes Per VRF

## Overview
**Test Suite ID**: 5.1.3
**Title**: Overlapping prefixes per VRF
**Objective**: Verify identical/overlapping prefixes configured or learned in different VRFs are handled independently (no RIB/FIB conflict and forwarding isolation).

**Topology**: `./testbeds/testbed_vs_2node.yaml`

## Test Description
This suite validates RIB/FIB isolation, data-plane forwarding, IPv6 behavior, controlled sharing (RT/MP-BGP), persistence across reboot, diagnostics and scale for overlapping prefixes across VRFs.

## Test Cases

### Test 5.1.3.1: Basic RIB isolation — identical IPv4 prefix in two VRFs

**Objective**: Verify same IPv4 prefix can exist in VRF_A and VRF_B and each VRF keeps its own route entry pointing to VRF-specific next-hop.

**Preconditions**:
- VRF_A and VRF_B created on DUT(s)
- Mechanism to originate/advertise prefix per VRF (static or per-VRF BGP) available

**Configuration Steps** (klish CLI):

```bash
# On D1 (smic_sonic1):
# Create VRFs
sonic(config)# ip vrf VRF_A
sonic(config-vrf)# exit
sonic(config)# ip vrf VRF_B
sonic(config-vrf)# exit

# Configure Loopback interfaces in VRF_A
sonic(config)# interface Loopback 10
sonic(conf-if-lo10)# ip vrf forwarding VRF_A
sonic(conf-if-lo10)# ip address 192.0.2.1/32
sonic(conf-if-lo10)# exit

# Configure Loopback interfaces in VRF_B
sonic(config)# interface Loopback 20
sonic(conf-if-lo20)# ip vrf forwarding VRF_B
sonic(conf-if-lo20)# ip address 192.0.2.1/32
sonic(conf-if-lo20)# exit

# Configure static route in VRF_A
sonic(config)# ip route vrf VRF_A 10.10.10.0/24 10.10.1.2

# Configure static route in VRF_B (same prefix, different next-hop)
sonic(config)# ip route vrf VRF_B 10.10.10.0/24 192.0.2.2

# On D2 (smic_sonic2):
# Create VRFs
sonic(config)# ip vrf VRF_A
sonic(config-vrf)# exit
sonic(config)# ip vrf VRF_B
sonic(config-vrf)# exit

# Configure Loopback interfaces
sonic(config)# interface Loopback 10
sonic(conf-if-lo10)# ip vrf forwarding VRF_A
sonic(conf-if-lo10)# ip address 192.0.2.2/32
sonic(conf-if-lo10)# exit

sonic(config)# interface Loopback 20
sonic(conf-if-lo20)# ip vrf forwarding VRF_B
sonic(conf-if-lo20)# ip address 192.0.2.2/32
sonic(conf-if-lo20)# exit
```

**Verification Commands** (click CLI):

```bash
# On D1 - Verify route in VRF_A
admin@sonic:~$ show ip route vrf VRF_A 10.10.10.0/24 -j

Expected Output:
{
  "10.10.10.0/24": [
    {
      "prefix": "10.10.10.0/24",
      "protocol": "static",
      "selected": true,
      "nexthops": [
        {
          "ip": "10.10.1.2",
          "active": true
        }
      ]
    }
  ]
}

# On D1 - Verify route in VRF_B
admin@sonic:~$ show ip route vrf VRF_B 10.10.10.0/24 -j

Expected Output:
{
  "10.10.10.0/24": [
    {
      "prefix": "10.10.10.0/24",
      "protocol": "static",
      "selected": true,
      "nexthops": [
        {
          "ip": "192.0.2.2",
          "active": true
        }
      ]
    }
  ]
}

# Verify no cross-VRF leakage
admin@sonic:~$ show ip route vrf VRF_A | grep 192.0.2.2
# Should NOT show 192.0.2.2 as next-hop for 10.10.10.0/24 in VRF_A

admin@sonic:~$ show ip route vrf VRF_B | grep 10.10.1.2
# Should NOT show 10.10.1.2 as next-hop for 10.10.10.0/24 in VRF_B
```

**Expected Result**: Per-VRF RIBs are independent and contain their own route entries.

**Timeout**: 90 seconds

**Cleanup**:
```bash
sonic(config)# no ip route vrf VRF_A 10.10.10.0/24 10.10.1.2
sonic(config)# no ip route vrf VRF_B 10.10.10.0/24 192.0.2.2
```

**Objective**: Confirm packets for identical prefix in VRF_A and VRF_B are forwarded to their respective next-hops (no cross-forwarding).

**Preconditions**:
- Subtest 5.1.3.1 passed
- Test hosts or traffic generator reachable behind NH_A and NH_B

**Configuration Steps**:
(Builds on 5.1.3.1 configuration)

**Verification Commands**:

### Test 5.1.3.3: IPv6 overlapping prefixes per VRF

**Objective**: Verify identical IPv6 prefix present in two VRFs remains isolated (RIB/FIB and forwarding).

**Preconditions**:
- IPv6 enabled and VRF IPv6 routing supported

**Configuration Steps** (klish CLI):

```bash
# On D1:
# Configure IPv6 Loopback in VRF_A
sonic(config)# interface Loopback 11
sonic(conf-if-lo11)# ip vrf forwarding VRF_A
sonic(conf-if-lo11)# ipv6 address 2001:db8:a::1/128
sonic(conf-if-lo11)# exit

# Configure IPv6 Loopback in VRF_B
sonic(config)# interface Loopback 21
sonic(conf-if-lo21)# ip vrf forwarding VRF_B
sonic(conf-if-lo21)# ipv6 address 2001:db8:a::1/128
sonic(conf-if-lo21)# exit

# Configure IPv6 static route in VRF_A
sonic(config)# ipv6 route vrf VRF_A 2001:db8:10::/64 2001:db8::2

# Configure IPv6 static route in VRF_B (same prefix, different next-hop)
sonic(config)# ipv6 route vrf VRF_B 2001:db8:10::/64 2001:db8:a::2
```

**Verification Commands** (click CLI):

```bash
# Verify IPv6 route in VRF_A
admin@sonic:~$ show ipv6 route vrf VRF_A 2001:db8:10::/64

Expected Output:
S>* 2001:db8:10::/64 [1/0] via 2001:db8::2, Ethernet4

# Verify IPv6 route in VRF_B
admin@sonic:~$ show ipv6 route vrf VRF_B 2001:db8:10::/64

Expected Output:
S>* 2001:db8:10::/64 [1/0] via 2001:db8:a::2, Loopback21

# Verify no cross-VRF leakage
admin@sonic:~$ show ipv6 route vrf VRF_A | grep 2001:db8:a::2
# Should NOT show 2001:db8:a::2 in VRF_A

admin@sonic:~$ show ipv6 route vrf VRF_B | grep 2001:db8::2
# Should NOT show 2001:db8::2 in VRF_B
```

**Expected Result**: IPv6 overlapping prefixes handled same as IPv4. Each VRF shows the IPv6 route to its next-hop; no cross-VRF leakage.

**Timeout**: 90 seconds

**Cleanup**:
```bash
sonic(config)# no ipv6 route vrf VRF_A 2001:db8:10::/64 2001:db8::2
sonic(config)# no ipv6 route vrf VRF_B 2001:db8:10::/64 2001:db8:a::2
```

### Test 5.1.3.4: Overlapping prefix with different route types (static vs BGP) across VRFs

**Objective**: Ensure static route in one VRF and BGP-learned route in another VRF do not conflict and are independently used.

**Preconditions**:
- Ability to configure static route and per-VRF BGP advertisements

**Configuration Steps** (klish CLI):

```bash
# On D1:
# Configure static route in VRF_A
sonic(config)# ip route vrf VRF_A 10.10.10.0/24 10.10.1.2

# Configure BGP in VRF_B
sonic(config)# router bgp 65001 vrf VRF_B
sonic(config-router-bgp)# neighbor 192.0.2.2 remote-as 65002
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# network 10.10.10.0/24
sonic(config-router-bgp-af)# exit
sonic(config-router-bgp)# exit

# On D2:
# Configure BGP in VRF_B to advertise the prefix
sonic(config)# router bgp 65002 vrf VRF_B
sonic(config-router-bgp)# neighbor 192.0.2.1 remote-as 65001
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# network 10.10.10.0/24
sonic(config-router-bgp-af)# exit
sonic(config-router-bgp)# exit
```

**Verification Commands** (click CLI):

```bash
# On D1 - Verify static route in VRF_A
admin@sonic:~$ show ip route vrf VRF_A 10.10.10.0/24

Expected Output:
S>* 10.10.10.0/24 [1/0] via 10.10.1.2, Ethernet4

# On D1 - Verify BGP route in VRF_B
admin@sonic:~$ show ip route vrf VRF_B 10.10.10.0/24

Expected Output:
B>* 10.10.10.0/24 [20/0] via 192.0.2.2, 00:01:23

# Verify BGP neighbor status in VRF_B
admin@sonic:~$ show ip bgp vrf VRF_B summary

# Verify route source independence
admin@sonic:~$ show ip route vrf VRF_A 10.10.10.0/24 | grep "S>"
admin@sonic:~$ show ip route vrf VRF_B 10.10.10.0/24 | grep "B>"
```

**Expected Result**: Different route origins for same prefix are isolated per VRF. VRF_A uses NH_static; VRF_B uses NH_bgp; no cross-influence.

**Timeout**: 90 seconds

**Cleanup**:
```bash
# On D1:
sonic(config)# no ip route vrf VRF_A 10.10.10.0/24 10.10.1.2
sonic(config)# no router bgp 65001 vrf VRF_B
```

### Test 5.1.3.5: Controlled sharing via RT import/export (intentional import)

**Objective**: Validate explicit import/export (route-target) allows a VRF to learn the overlapping prefix from another VRF when configured.

**Preconditions**:
- MP-BGP and RT functionality available in environment

**Configuration Steps** (klish CLI):

```bash
# On D1:
# Configure BGP with MP-BGP VPN support
sonic(config)# router bgp 65001
sonic(config-router-bgp)# address-family ipv4 vpn
sonic(config-router-bgp-af)# exit
sonic(config-router-bgp)# exit

# Configure VRF_A with export RT
sonic(config)# router bgp 65001 vrf VRF_A
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# route-target export 65001:10
sonic(config-router-bgp-af)# network 10.10.10.0/24
sonic(config-router-bgp-af)# exit
sonic(config-router-bgp)# exit

# Configure VRF_B with import RT
sonic(config)# router bgp 65001 vrf VRF_B
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# route-target import 65001:10
sonic(config-router-bgp-af)# exit
sonic(config-router-bgp)# exit
```

**Verification Commands** (click CLI):

```bash
# Verify VRF_A advertises with RT
admin@sonic:~$ show bgp vpnv4 vrf VRF_A

Expected Output:
Network          Next Hop            Metric LocPrf Weight Path
*> 10.10.10.0/24    0.0.0.0                  0         32768 ?
Extended Community: RT:65001:10

# Verify VRF_B imports the route
admin@sonic:~$ show ip route vrf VRF_B 10.10.10.0/24

Expected Output:
B>* 10.10.10.0/24 [200/0] via 192.0.2.1 (VRF_A), 00:02:15

# Verify RT attributes
admin@sonic:~$ show bgp vrf VRF_B 10.10.10.0/24 json

Expected JSON includes:
{
  "paths": [
    {
      "valid": true,
      "extendedCommunity": {
        "string": "RT:65001:10"
      }
    }
  ]
}
```

**Expected Result**: Controlled sharing works; VRF_B contains the prefix only after RT import configured; RT attribute visible in BGP NLRI. Isolation otherwise maintained.

**Timeout**: 120 seconds

**Cleanup**:
```bash
sonic(config)# router bgp 65001 vrf VRF_A
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# no route-target export 65001:10
sonic(config-router-bgp-af)# exit

sonic(config)# router bgp 65001 vrf VRF_B
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# no route-target import 65001:10
sonic(config-router-bgp-af)# exit
```

### Test 5.1.3.7: Intentional misconfiguration leak (lab-only)

**Objective**: Deliberately create misconfiguration (e.g., wrong RT/redistribute) to observe and document how leakage occurs and how to revert.

**Preconditions**:
- Lab environment only; approvals in place

**Configuration Steps** (klish CLI):

```bash
# Intentionally misconfigure: leak from VRF_A into global table
# WARNING: This is a negative test - do NOT do this in production!

# On D1:
# Configure VRF_A with BGP
sonic(config)# router bgp 65001 vrf VRF_A
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# network 10.10.10.0/24
sonic(config-router-bgp-af)# exit
sonic(config-router-bgp)# exit

# Misconfiguration: Import from VRF into global
sonic(config)# router bgp 65001
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# import vrf VRF_A
sonic(config-router-bgp-af)# exit
```

**Verification Commands** (click CLI):

```bash
# Observe the leak
admin@sonic:~$ show ip route 10.10.10.0/24

Expected Output (showing leak):
B>* 10.10.10.0/24 [200/0] via 192.0.2.1 (VRF_A imported), 00:00:15

# Check global BGP table
admin@sonic:~$ show ip bgp 10.10.10.0/24

# Collect system logs
admin@sonic:~$ sudo tail -100 /var/log/syslog | grep -i bgp

# Collect FRR logs
admin@sonic:~$ sudo docker exec -it bgp vtysh -c "show log" | tail -50
```

**Rollback Steps**:

```bash
# Immediately revert the misconfiguration
sonic(config)# router bgp 65001
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# no import vrf VRF_A
sonic(config-router-bgp-af)# exit

# Verify leak is fixed
admin@sonic:~$ show ip route 10.10.10.0/24
# Should show "Network not in table" or similar

# Verify VRF_A still has the route
admin@sonic:~$ show ip route vrf VRF_A 10.10.10.0/24
```

**Expected Result**: Leak occurs only when explicit misconfig present; logs and artifacts show cause and required rollback steps. Misconfiguration leads to documented leakage; operators can reproduce and remediate.

**Timeout**: 180 seconds

### Test 5.1.3.8: Scale: many VRFs with the same prefix (lab/manual)

**Objective**: Evaluate behavior when many VRFs (N) host identical prefix — verify per-VRF RIB/FIB scale and resource impact.

**Preconditions**:
- Lab harness able to create many VRFs or simulate them
- DUT supports required scale

**Configuration Steps** (klish CLI):

```bash
# Script to create N VRFs with identical prefix
# Example for 50 VRFs:

# On D1:
for i in {1..50}; do
  sonic(config)# ip vrf VRF_$i
  sonic(config-vrf)# exit

  sonic(config)# interface Loopback $((100 + i))
  sonic(conf-if-lo$((100 + i)))# ip vrf forwarding VRF_$i
  sonic(conf-if-lo$((100 + i)))# ip address 192.0.2.$i/32
  sonic(conf-if-lo$((100 + i)))# exit

  sonic(config)# ip route vrf VRF_$i 10.10.10.0/24 10.10.1.$i
done
```

**Verification Commands** (click CLI):

```bash
# Count VRFs
admin@sonic:~$ show ip vrf | wc -l

# Verify each VRF has the route
for i in {1..50}; do
  echo "Checking VRF_$i:"
  admin@sonic:~$ show ip route vrf VRF_$i 10.10.10.0/24
done

# Monitor resource usage
admin@sonic:~$ show system-memory
admin@sonic:~$ show processes cpu

# Check RIB/FIB entry counts
admin@sonic:~$ vtysh -c "show ip route summary"

Expected Output includes:
VRF VRF_1: 1 routes
VRF VRF_2: 1 routes
...
VRF VRF_50: 1 routes

# Verify no cross-VRF leakage
admin@sonic:~$ show ip route vrf VRF_1 | grep "10.10.1.2"
# Should NOT show next-hop from VRF_2
```

**Expected Result**: Device programs per-VRF entries and handles scale without cross-leakage; resource usage within expected limits. Device supports expected VRF-scale; document limits if any.

**Timeout**: 1800 seconds (30 minutes for scale test)

**Cleanup**:
```bash
# Remove all test VRFs
for i in {1..50}; do
  sonic(config)# no ip route vrf VRF_$i 10.10.10.0/24 10.10.1.$i
  sonic(config)# no ip vrf VRF_$i
done
```

### Test 5.1.3.9: Diagnostics: BGP/MP-BGP attributes and captures for overlapping-prefix investigation

**Objective**: Capture BGP/MP-BGP NLRI (RD/RT), system logs and tcpdumps when overlapping-prefix actions occur to aid debugging.

**Preconditions**:
- Access to packet-capture and system logs on DUT/peers

**Configuration Steps**:

```bash
# Start packet capture on D1 BGP sessions
admin@sonic:~$ sudo tcpdump -i Ethernet4 -w /tmp/overlap_vrf.pcap 'tcp port 179' &
TCPDUMP_PID=$!

# Configure VRFs and BGP with MP-BGP (from 5.1.3.5)
# ... (see 5.1.3.5 configuration) ...

# Enable BGP debugging
admin@sonic:~$ sudo docker exec -it bgp vtysh
sonic# configure terminal
sonic(config)# debug bgp updates
sonic(config)# debug bgp zebra
sonic(config)# log file /var/log/frr/bgp_debug.log
sonic(config)# exit
sonic# exit
```

**Verification Commands** (click CLI):

```bash
# Collect BGP VPNv4 information
admin@sonic:~$ show bgp vpnv4 all json > /tmp/bgp_vpnv4_all.json

# Collect per-VRF BGP information
admin@sonic:~$ show bgp vrf VRF_A ipv4 unicast json > /tmp/bgp_vrf_a.json
admin@sonic:~$ show bgp vrf VRF_B ipv4 unicast json > /tmp/bgp_vrf_b.json

# Verify RD/RT attributes in captured data
admin@sonic:~$ cat /tmp/bgp_vpnv4_all.json | jq '.routes[] | select(.prefix=="10.10.10.0/24")'

Expected Output includes:
{
  "prefix": "10.10.10.0/24",
  "rd": "192.0.2.1:1",
  "paths": [
    {
      "extendedCommunity": {
        "string": "RT:65001:10"
      },
      "originVrf": "VRF_A"
    }
  ]
}

# Collect system logs
admin@sonic:~$ sudo tail -500 /var/log/syslog > /tmp/syslog_bgp_test.log

# Collect FRR logs
admin@sonic:~$ sudo docker exec -it bgp cat /var/log/frr/bgp_debug.log > /tmp/frr_bgp_debug.log

# Stop tcpdump
admin@sonic:~$ sudo kill $TCPDUMP_PID

# Analyze pcap for BGP UPDATE messages
admin@sonic:~$ sudo tcpdump -r /tmp/overlap_vrf.pcap -v -X 'tcp port 179 and (tcp[20:2] = 0x0200)'

# Archive all artifacts
admin@sonic:~$ tar -czf /tmp/bgp_513_diagnostics_$(date +%Y%m%d_%H%M%S).tar.gz \
  /tmp/overlap_vrf.pcap \
  /tmp/bgp_vpnv4_all.json \
  /tmp/bgp_vrf_*.json \
  /tmp/syslog_bgp_test.log \
  /tmp/frr_bgp_debug.log
```

**Expected Result**: Diagnostics provide sufficient evidence to trace ownership and propagation of overlapping prefixes. Captured NLRI includes RD/RT attributes and shows origin VRF; logs indicate import/export decisions.

**Timeout**: 300 seconds

**Cleanup**:
```bash
# Disable BGP debugging
admin@sonic:~$ sudo docker exec -it bgp vtysh -c "configure terminal" -c "no debug bgp updates" -c "no debug bgp zebra"

# Remove diagnostic files (optional)
```

## Common Issues and Troubleshooting

1. **VRF not created**: Verify `show ip vrf` output
2. **Route not installed**: Check `show ip route vrf <vrf>` and verify next-hop reachability
3. **BGP session not established**: Verify `show ip bgp vrf <vrf> summary`
4. **RT import/export not working**: Check MP-BGP configuration with `show bgp vpnv4 all`
5. **Reboot persistence failure**: Verify `config save` was executed before reboot
