# BGP Test ID 4.1.4: Route-refresh During Policy Change

## Test Overview

**Test ID:** 4.1.4
**Title:** Route-refresh during policy change
**Topology:** `./testbeds/testbed_vs_2node.yaml` (2 DUTs)
**CLI Type:** klish (configuration), click (show commands)

## Objective

Verify route-refresh capability allows applying/refreshing policy (route-maps) without resetting BGP session.

## Description

These subtests validate route-refresh and soft-reconfiguration flows:
- Change inbound/outbound policies and trigger refresh (soft or explicit)
- Behavior when neighbor supports/doesn't support route-refresh
- Interaction with BGP soft-reconfig and refresh capability
- Effect on RIB/FIB and route selection
- IPv6, large-scale and diagnostic cases

## Topology Requirements

- **Devices:** 2 DUTs (D1, D2)
- **Links:** At least 1 direct connection between DUTs
- **Testbed:** `./testbeds/testbed_vs_2node.yaml`

## Test Cases

---

### Test 4.1.4.1: Basic route-refresh (inbound policy change) - IPv4

**Objective:** Modify inbound route-map on DUT and trigger route-refresh; verify routes re-evaluated and session stays Established.

**Preconditions:**
- BGP sessions Established between DUT and peer
- Peer supports route-refresh capability
- A test prefix is advertised by peer and present in DUT BGP RIB

**Topology:**
```
DUT1 (D1) <-----> DUT2 (D2)
AS 65001         AS 65002
10.1.1.1         10.1.1.2
```

**Configuration Steps:**

1. **Initial BGP Setup on DUT1:**
```bash
# SONiC klish CLI
sonic# configure terminal
sonic(config)# router bgp 65001
sonic(config-router-bgp)# neighbor 10.1.1.2 remote-as 65002
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# neighbor 10.1.1.2 activate
sonic(config-router-bgp-af)# exit
sonic(config-router-bgp)# exit
```

2. **Configure test prefix on DUT2:**
```bash
sonic# configure terminal
sonic(config)# router bgp 65002
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# network 192.168.100.0/24
sonic(config-router-bgp-af)# exit
```

3. **Verify baseline (click CLI):**
```bash
show ip bgp summary
show ip bgp 192.168.100.0/24 json
```

4. **Create inbound route-map on DUT1 to deny test prefix:**
```bash
sonic# configure terminal
sonic(config)# ip prefix-list DENY_TEST seq 10 permit 192.168.100.0/24
sonic(config)# route-map RM-IN deny 10
sonic(config-route-map)# match ip address prefix-list DENY_TEST
sonic(config-route-map)# exit
sonic(config)# route-map RM-IN permit 20
sonic(config-route-map)# exit
```

5. **Apply route-map inbound:**
```bash
sonic(config)# router bgp 65001
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# neighbor 10.1.1.2 route-map RM-IN in
sonic(config-router-bgp-af)# exit
```

6. **Trigger route-refresh (click CLI):**
```bash
sonic bgp soft in 10.1.1.2
# or
clear ip bgp 10.1.1.2 soft in
```

**Verification:**
```bash
# Check BGP session status
show ip bgp summary

# Verify route is withdrawn
show ip bgp 192.168.100.0/24 json

# Check BGP neighbor details
show ip bgp neighbors 10.1.1.2 json

# Verify no session resets
show logging | grep BGP
```

**Expected Results:**
- BGP session remains Established (no flaps)
- RIB reflects policy change (route withdrawn per route-map)
- No unexpected session reset events in logs
- Policy applied via route-refresh without session teardown

**Timeout:** 120 seconds

**Cleanup:**
```bash
sonic# configure terminal
sonic(config)# router bgp 65001
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# no neighbor 10.1.1.2 route-map RM-IN in
sonic(config-router-bgp-af)# exit
sonic(config)# no route-map RM-IN
sonic(config)# no ip prefix-list DENY_TEST
```

### Test 4.1.4.2: Basic route-refresh (outbound policy change) - IPv4

**Objective:** Change outbound policy on DUT and trigger refresh so peer receives updated attributes without session teardown.

**Preconditions:**
- BGP Established and peer accepts updates from DUT

**Configuration Steps:**

1. **Baseline check (click CLI):**
```bash
show ip bgp neighbors 10.1.1.2 advertised-routes
```

2. **Configure test prefix on DUT1:**
```bash
sonic# configure terminal
sonic(config)# router bgp 65001
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# network 172.16.0.0/24
sonic(config-router-bgp-af)# exit
```

3. **Create outbound route-map to change MED:**
```bash
sonic(config)# route-map RM-OUT permit 10
sonic(config-route-map)# match ip address prefix-list TEST_PREFIX
sonic(config-route-map)# set metric 100
sonic(config-route-map)# exit
sonic(config)# route-map RM-OUT permit 20
sonic(config-route-map)# exit
sonic(config)# ip prefix-list TEST_PREFIX seq 10 permit 172.16.0.0/24
```

4. **Apply outbound route-map:**
```bash
sonic(config)# router bgp 65001
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# neighbor 10.1.1.2 route-map RM-OUT out
sonic(config-router-bgp-af)# exit
```

5. **Trigger outbound route-refresh:**
```bash
sonic bgp soft out 10.1.1.2
# or
clear ip bgp 10.1.1.2 soft out
```

**Verification:**
```bash
# Check session status
show ip bgp summary

# Verify advertised routes with new MED
show ip bgp neighbors 10.1.1.2 advertised-routes

# Check on DUT2 to see updated attributes
show ip bgp 172.16.0.0/24 json
```

**Expected Results:**
- Peer receives new attributes (MED=100)
- Session remains Established
- No DROP or reset in logs
- Outbound policy change takes effect via route-refresh

**Timeout:** 120 seconds

**Cleanup:**
```bash
sonic# configure terminal
sonic(config)# router bgp 65001
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# no neighbor 10.1.1.2 route-map RM-OUT out
sonic(config-router-bgp-af)# no network 172.16.0.0/24
sonic(config-router-bgp-af)# exit
sonic(config)# no route-map RM-OUT
sonic(config)# no ip prefix-list TEST_PREFIX
```

```bash
# Check memory usage (soft-reconfig buffer)
show processes memory | grep bgp
```

**Expected Results:**
- Policy applied successfully using cached routes
- Session did not flap
- Memory usage monitored for soft-reconfig buffer impact

**Timeout:** 180 seconds

**Cleanup:**
```bash

sonic(config)# router bgp 65001
sonic(config-router-bgp)# address-family ipv4 unicast
sonic(config-router-bgp-af)# no neighbor 10.1.1.2 soft-reconfiguration inbound
```

## Notes and Best Practices

1. **CLI Mode:**
   - Use **klish** mode for configuration commands
   - Use **click** mode for show commands
   - Some platforms may support both modes for show commands

2. **Capabilities:**
   - Route-Refresh capability is defined in RFC 2918
   - Enhanced Route-Refresh is defined in RFC 7313
   - Check capability support: `show bgp neighbor <peer> capabilities`

3. **Soft-Reconfiguration:**
   - Requires memory to store received routes
   - Use when peer doesn't support route-refresh
   - Enable: `neighbor <peer> soft-reconfiguration inbound`

4. **Route-Refresh Types:**
   - **Normal refresh (subtype 0):** Complete route re-advertisement
   - **BoRR (Begin of Route Refresh):** Enhanced refresh begin marker
   - **EoRR (End of Route Refresh):** Enhanced refresh end marker

5. **Performance Considerations:**
   - Large route tables (>10k routes) may take significant time to refresh
   - Monitor CPU and memory during refresh operations
   - Consider rate-limiting or scheduling refreshes during maintenance windows

6. **Troubleshooting:**
   - Check capabilities before assuming route-refresh support
   - Verify route-maps are correctly applied (in/out direction)
   - Use packet captures to see actual BGP messages
   - Check logs for errors or warnings

7. **Lab-Only Tests:**
   - Tests 4.1.4.6 (large-scale) and 4.1.4.8 (malformed messages) are lab-only
   - Require controlled environment and approvals
   - Not suitable for production networks

8. **Cleanup:**
   - Always revert configurations after tests
   - Verify session stability after cleanup
   - Archive diagnostic artifacts before removal
